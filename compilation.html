Compilation and diagnostics

Guide for the current test build. Download and release notes are linked from the overview.

Configure BSP, visibility and lighting stages in the Compile panel. GPU compilation uses an independent window with progress, Stop and Problems. The finished log returns to NoDraw with filters, explanations and links to map coordinates, so diagnosing a build stays part of the editing workflow.

Important: GPU lighting shares the graphics device with other applications. If a build runs out of graphics memory or loses the device, retry the lighting stage on CPU.

Workflow

  1. Open Compile, choose the stages and inspect their command lines. CPU lighting is the default; GPU is an explicit Expert option.
  2. The independent GPU compile window shows progress, log, Problems and Stop. After the run, the log returns to the main Compile panel for filtering and map-coordinate navigation.
  3. Out-of-memory and device-loss failures can retry the lighting stage on CPU. Save a diagnostic log for failed builds; warnings about a model are separate from the compiler exit status.
